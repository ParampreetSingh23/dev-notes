1. Why Go?

Go (often called Golang) is a compiled, statically typed, garbage-collected language created at Google. It's popular for backend servers, cloud tools (Docker and Kubernetes are written in Go), and command-line programs.

Speed: two different kinds

Kind of speed How Go compares
Execution speed (how fast the program runs) Much faster than interpreted languages (Python, JavaScript, Ruby, PHP). Roughly similar to Java and C#. Slower than Rust, C and C++.
Compilation speed (how fast code turns into a program) Much faster than most compiled languages. Large Go programs usually build in seconds, while big Java or C++ projects can take many minutes.

Fast compilation matters more than it sounds: you can test, fix and deploy quickly, so you iterate faster.

Compiled vs interpreted

Computers only understand machine code (binary instructions for the CPU). Human-readable code has to be translated.

Compiled (Go, Rust, C) Interpreted (Python, JavaScript)
Translation happens Once, before running (go build) Every time, while running
You ship A single executable file The source code
User needs Nothing extra The interpreter installed (e.g. Python)
Source code visible to user No Yes
Errors like typos found At compile time Often only at runtime
Runtime speed Faster (no translation at runtime) Slower 
main.go  ──go build──►  hello (executable)  ──run directly on any matching OS──►
Why this makes deployment easy

A Go server compiles into one binary with no runtime dependencies. Copy it to a server and run it. There's no need to install Go, Node or Python there.

Compile-time errors vs runtime errors

  • A compile-time error stops the program from being built at all, e.g. a missing ) gives syntax error. You find it immediately.
  • A runtime error happens while the program runs, possibly in production. Go's compiler and type system catch many mistakes early, so fewer reach runtime.

Memory and the Go runtime

Language Memory management Memory use
C, C++, Rust Manual (Rust checks it at compile time) Lowest
Go Automatic (garbage collected) via a small runtime compiled into every binary Low to medium
Java, C# Automatic, inside a full virtual machine (JVM / .NET) Highest

The Go runtime is a small chunk of code included in every Go program. It handles garbage collection (freeing memory that's no longer used) and schedules goroutines (section 17). It makes Go slightly slower than Rust or C, but it's far lighter than a JVM. In one benchmark of an idle web server, a Go server used roughly 100× less memory than the Java one, though Rust used about half of Go's.

Static, strong typing

Every variable has a fixed type known at compile time:

username := "gopher"
username = 42 // ✗ compile error: cannot use 42 (untyped int constant) as string value

Mixing types is an error, not a silent conversion:

password := 12345
auth := "user:" + password
// ✗ invalid operation: mismatched types string and int

3. Variables and types

Basic types

Category Types Notes
Boolean bool true / false
String string Text in double quotes "hi" or backticks for raw strings `C:\path`
Signed integers int, int8, int16, int32, int64 Whole numbers, positive or negative
Unsigned integers uint, uint8, uint16, uint32, uint64, uintptr Whole numbers ≥ 0 only
Floats float32, float64 Numbers with a decimal part, e.g. 3.14
Complex complex64, complex128 Imaginary numbers (rarely used)
Aliases byte = uint8, rune = int32 byte for raw data; rune for one Unicode character

Size matters

The number is the size in bits. More bits means a bigger range of values, at the cost of more memory:

Type Range
uint8 0 to 255
uint16 0 to 65,535
int8 −128 to 127
int64 about ±9.2 × 10¹⁸

int and uint are 32 or 64 bits depending on the CPU (64 bits on almost all modern machines).

Use the default types

Stick to int, uint, float64, string, bool (and complex128 if you ever need it). Only reach for sized types like int8 or float32 when memory or performance really matters, e.g. huge arrays. Mixing sizes means lots of conversions and more chances for bugs.

Trivia: a byte is 8 bits; a nibble is 4 bits.

Declaring variables

// Long form: name, type, (optional) value
var smsSendingLimit int
var costPerSMS float64
var hasPermission bool
var username string

// Short form: := declares AND infers the type (most common inside functions)
congrats := "happy birthday" // string
numCars := 10                // int
penniesPerText := 2.0        // float64 (the .0 makes it a float)

// Several on one line
averageOpenRate, displayMessage := 0.23, "is the average open rate"
Form Where it works Use when
var x int Anywhere (also package level) You want the zero value, or need a specific type
x := 5 Only inside functions Almost always inside functions
:= is still static typing

x := 5 doesn't make x a "loose" variable; it's an int forever. Go just worked the type out for you.

Zero values

Every type has a zero value used when you don't assign anything. There's no "undefined" in Go:

Type Zero value
Numbers 0 / 0.0
bool false
string "" (empty string)
Pointers, slices, maps, channels, functions, interfaces nil
Structs Each field set to its own zero value

Type conversion

Go never converts types automatically. Convert explicitly with Type(value):

temperatureInt := 88
temperatureFloat := float64(temperatureInt) // 88.0

accountAge := 2.6
accountAgeInt := int(accountAge) // 2 (truncates: the .6 is dropped, not rounded)

Unused variables

Go refuses to compile if you declare a local variable and never use it:

declared and not used: lastName

This keeps code clean. Use the blank identifier _ to deliberately ignore a value (section 7).

4. Constants

const premiumPlanName = "Premium Plan"
const basicPlanName = "Basic Plan"

premiumPlanName = "Other" // ✗ cannot assign to premiumPlanName
  • Declared with const. They can't use :=.
  • They can't change after declaration.

Constants are computed at compile time

Unlike JavaScript's const (which only means "can't reassign"), a Go constant's value must be known when the program compiles. You can build constants from other constants:

const secondsInMinute = 60
const minutesInHour = 60
const secondsInHour = secondsInMinute * minutesInHour // 3600, computed by the compiler

const firstName = "Ada"
const lastName = "Lovelace"
const fullName = firstName + " " + lastName // ✓ all inputs are constants

But you can't use a runtime value:

const now = time.Now() // ✗ time.Now() is only known at runtime

Grouped constants and iota (Extra)

const (
	Pending = iota // 0
	Approved       // 1
	Rejected       // 2
)

iota counts up from 0 inside a const ( ... ) block. It's Go's usual way to make enum-like values.

6. Conditionals

if / else if / else

if height > 6 {
	fmt.Println("You are super tall!")
} else if height > 4 {
	fmt.Println("You are tall enough!")
} else {
	fmt.Println("You are not tall enough!")
}
  • No parentheses around the condition, but the braces are required.
  • Conditions are checked top to bottom; the first true one runs and the rest are skipped.
  • else if and else are optional.
Operator Meaning
==, != Equal, not equal
<, >, <=, >= Comparisons
&& AND: both sides true
|| OR: at least one side true
! NOT

The initial statement

An if can declare a variable that only exists inside the if/else blocks:

// Normal way
length := getLength(email)
if length < 1 {
	fmt.Println("Email is invalid")
}

// With an initial statement: length is scoped to the if block
if length := getLength(email); length < 1 {
	fmt.Println("Email is invalid")
}
// length doesn't exist here

Benefits: shorter code, and the variable can't be accidentally reused later. You'll see this pattern constantly with errors: if err := doThing(); err != nil { ... }.

switch (Extra)

switch plan {
case "free":
	fmt.Println("1 retry")
case "pro", "enterprise": // several values in one case
	fmt.Println("unlimited retries")
default:
	fmt.Println("unknown plan")
}

Unlike C or JavaScript, Go's switch doesn't fall through: only the matching case runs, so you don't need break.

7. Functions

Signature

func sub(x int, y int) int {
	return x - y
}

The first line, func sub(x int, y int) int, is the function signature. It tells callers everything they need: the name, inputs and output types. The body is an implementation detail.

  • The type comes after the name (x int). Go chose this because it reads like English, left to right: "x is an int".
  • If consecutive parameters share a type, write it once:
func add(x, y int) int { return x + y }

func createUser(firstName, lastName string, age int) {}

Pass by value

Go copies arguments into functions. Changing the copy doesn't affect the caller:

func increment(x int) {
	x++ // changes the local copy only
}

func main() {
	x := 5
	increment(x)
	fmt.Println(x) // still 5
}

Fix: return the new value and reassign it:

func increment(x int) int {
	x++
	return x
}

x = increment(x) // 6

(Pointers, section 15, are the other fix. Slices and maps behave differently; see sections 12 and 13.)

Multiple return values

func getNames() (string, string) {
	return "John", "Doe"
}

firstName, lastName := getNames()
firstName, _ := getNames() // _ ignores the second value
  • Multiple return types go in parentheses; a single return type doesn't need them.
  • _ (the blank identifier) explicitly throws a value away. The compiler removes it entirely. This is how you satisfy the "no unused variables" rule.

Named return values

func getCoords() (x, y int) {
	// x and y are already declared with their zero values (0, 0)
	x = 5
	y = 6
	return // "naked" return: returns x, y automatically
}
Recommendation
Named returns Good documentation: func dims() (width, height, length int) is much clearer than (int, int, int). Use them freely.
Naked returns (return with nothing) Hurt readability. Only for very short functions. Prefer explicit return x, y.

An explicit return always wins: with return 5, 6, those values are returned, whatever x and y hold.

Early returns (guard clauses)

Return as soon as you know the answer, instead of nesting if/else:

// ✗ Nested: hard to follow
func getInsuranceAmount(s status) int {
	amount := 0
	if !s.hasInsurance() {
		amount = 1
	} else {
		if s.isTotaled() {
			amount = 10000
		} else {
			if s.isDented() {
				amount = 160
			} else {
				amount = 0
			}
		}
	}
	return amount
}

// ✓ Guard clauses: read straight down
func getInsuranceAmount(s status) int {
	if !s.hasInsurance() {
		return 1
	}
	if s.isTotaled() {
		return 10000
	}
	if s.isDented() {
		return 160
	}
	return 0
}

Guard clauses give a linear path through the logic: check, bail out, move on. This style is idiomatic in Go, especially for errors.

Functions as values

A function's type is its signature. func(int, int) int is a different type from func(int, int, int) int.

func aggregate(a, b, c int, arithmetic func(int, int) int) int {
	return arithmetic(arithmetic(a, b), c)
}

Reading complex signatures: func f(func(int, int) int, int) int is "a function f that takes a function (which takes two ints and returns an int) and an int, and returns an int". More in section 14.

8. Structs

A struct groups related fields into one type, like an object in JavaScript or a dictionary in Python, but with fixed fields and types.

type messageToSend struct {
	phoneNumber int
	message     string
}

msg := messageToSend{
	phoneNumber: 148255510981,
	message:     "Thanks for signing up",
}
fmt.Println(msg.message) // dot operator reads fields
msg.phoneNumber = 0      // and writes them

An empty literal car{} sets every field to its zero value.

Nested structs

type wheel struct {
	radius   int
	material string
}

type car struct {
	make       string
	model      string
	frontWheel wheel
	backWheel  wheel
}

myCar := car{}
myCar.frontWheel.radius = 5

Validating struct fields

type user struct {
	name   string
	number int
}

type messageToSend struct {
	message   string
	sender    user
	recipient user
}

func canSendMessage(m messageToSend) bool {
	if m.sender.name == "" {
		return false
	}
	if m.recipient.name == "" {
		return false
	}
	if m.sender.number == 0 {
		return false
	}
	if m.recipient.number == 0 {
		return false
	}
	return true
}

Zero values double as "missing": an empty name or zero number means it wasn't set.

Anonymous structs

A struct type with no name, created and used in one place:

myCar := struct {
	make  string
	model string
}{
	make:  "Tesla",
	model: "Model 3",
}

// Also common nested inside another struct
type car struct {
	make  string
	wheel struct {
		radius   int
		material string
	}
}

Use them only when the type is needed exactly once, e.g. the shape of a one-off JSON response. Otherwise prefer named structs; they're clearer and reusable.

Embedded structs

Embedding puts one struct's fields directly into another, without a field name:

type car struct {
	make  string
	model string
}

type truck struct {
	car        // embedded: no field name
	bedSize int
}

lanesTruck := truck{
	bedSize: 10,
	car: car{ // in the literal you still write it like a field
		make:  "Toyota",
		model: "Tacoma",
	},
}

fmt.Println(lanesTruck.model) // ✓ promoted to the top level (not lanesTruck.car.model)
Nested Embedded
Declaration frontWheel wheel car (type only)
Access t.frontWheel.radius t.model (promoted)
Feels like "has a" "is a kind of"
Not inheritance

Go is not object-oriented: there are no classes or class inheritance. Embedding is mostly shorthand for "copy these fields (and methods) in here".

Methods

A method is a function with a special receiver parameter written before the name:

type rect struct {
	width  int
	height int
}

func (r rect) area() int {
	return r.width * r.height
}

r := rect{width: 5, height: 10}
fmt.Println(r.area()) // 50

Why use a method for area instead of storing it as a field? A stored area could go out of sync if someone changes the width and forgets the area. Computing it keeps one single source of truth.

type authenticationInfo struct {
	username string
	password string
}

func (a authenticationInfo) getBasicAuth() string {
	return fmt.Sprintf("Authorization: Basic %s:%s", a.username, a.password)
}

Methods that need to change the struct use pointer receivers (section 15).

9. Interfaces

An interface is a set of method signatures. Any type that has all those methods automatically satisfies the interface.

type shape interface {
	area() float64
	perimeter() float64
}

type rect struct{ width, height float64 }

func (r rect) area() float64      { return r.width * r.height }
func (r rect) perimeter() float64 { return 2*r.width + 2*r.height }

type circle struct{ radius float64 }

func (c circle) area() float64      { return math.Pi * c.radius * c.radius }
func (c circle) perimeter() float64 { return 2 * math.Pi * c.radius }

// Accepts ANY shape: rect, circle, or future types
func printShape(s shape) {
	fmt.Printf("area %.2f, perimeter %.2f\n", s.area(), s.perimeter())
}

printShape doesn't know or care whether it got a rectangle or a circle. That's the power of interfaces: one function, many types.

Implemented implicitly

There's no implements keyword in Go. If the methods match, the type satisfies the interface:

type employee interface {
	getName() string
	getSalary() int
}

type contractor struct {
	name         string
	hourlyPay    int
	hoursPerYear int
}

func (c contractor) getName() string { return c.name }
func (c contractor) getSalary() int  { return c.hourlyPay * c.hoursPerYear }
// contractor is now an employee: nothing else to declare

Benefits:

  • The type doesn't need to know the interface exists. This decouples code.
  • A type can satisfy many interfaces at once.

Multiple interfaces

type expense interface{ cost() float64 }
type printer interface{ print() }

type email struct {
	isSubscribed bool
	body         string
}

func (e email) cost() float64 {
	if !e.isSubscribed {
		return 0.05 * float64(len(e.body))
	}
	return 0.01 * float64(len(e.body))
}

func (e email) print() { fmt.Println(e.body) }
// email satisfies both expense and printer

Note float64(len(e.body)): len returns an int, and Go won't multiply an int by a float64 without a conversion.

The empty interface

interface{} (or its alias any) has no methods, so every type satisfies it. It's useful for "anything" (like fmt.Println arguments), but you can't call anything on it without checking its type first.

Name your interface parameters

// Unclear: what are the two strings?
type copier interface {
	copy(string, string) int
}

// Clear: names document intent
type copier interface {
	copy(sourceFile string, destinationFile string) (bytesCopied int)
}

The names are optional for the compiler, but they make the code much easier to understand.

Type assertions

Get the concrete type back out of an interface:

c, ok := s.(circle)
if ok {
	fmt.Println(c.radius) // s really was a circle
}
  • ok is true if s held a circle; then c is that circle.
  • If not, ok is false and c is the zero value.
  • Writing c := s.(circle) without ok panics if the type is wrong, so always use the two-value form.
func getExpenseReport(e expense) (string, float64) {
	em, ok := e.(email)
	if ok {
		return em.toAddress, em.cost()
	}
	s, ok := e.(sms)
	if ok {
		return s.toPhoneNumber, s.cost()
	}
	return "", 0.0
}

Type switches

The cleaner way to do several assertions in a row:

func getExpenseReport(e expense) (string, float64) {
	switch v := e.(type) {
	case email:
		return v.toAddress, v.cost() // v is an email here
	case sms:
		return v.toPhoneNumber, v.cost() // v is an sms here
	default:
		return "", 0.0
	}
}

Clean interface rules

  1. Keep interfaces small. The best interfaces have one or two methods. Example from the standard library:
    type Stringer interface {
    String() string
}
    A larger file-like interface (Read, Write, Seek, Close…) is still fine if it's the minimum needed to describe the concept.
  2. Interfaces shouldn't know about the types that satisfy them. ✗ isFireTruck() bool on a car interface. Use a type switch if you really need the concrete type.
  3. Interfaces are not classes. They have no constructors, no hierarchy and no implementation. Each type still writes its own methods; an interface only lets you use different types in the same place.

10. Errors

Errors are values

Go has no try/catch. A function that can fail returns an error as its last return value:

user, err := getUser()
if err != nil {
	fmt.Println(err)
	return
}
// use user safely here

profile, err := getUserProfile(user.ID)
if err != nil {
	fmt.Println(err)
	return
}
// use profile
Value of err Meaning
nil Success: nothing went wrong
Not nil Something failed; err.Error() describes what

Why Go does it this way

Compared with JavaScript's try/catch:

// JavaScript: user only exists inside the try block
try {
  const user = getUser();
  const profile = getUserProfile(user.id); // forced inside the same block
} catch (err) {
  console.log(err); // which call failed? can't tell
}
  1. Every error is visible in the signature. func getUser() (user, error) tells you it can fail. In JavaScript you can't tell whether a function throws without reading its body.
  2. Each error is handled where it happens. There's no nesting of try blocks to handle two calls differently, and no scope problems.
  3. You're forced to think about each failure. The if err != nil pattern is verbose, but deliberate.

The error interface

type error interface {
	Error() string
}

That's all an error is: any type with an Error() string method. Example from the standard library:

i, err := strconv.Atoi("42b")
if err != nil {
	fmt.Println("couldn't convert:", err)
	// couldn't convert: strconv.Atoi: parsing "42b": invalid syntax
	return
}

Returning errors

Convention: on error, return zero values for everything else, plus the error:

func sendSMSToCouple(msgToCustomer, msgToSpouse string) (float64, error) {
	costForCustomer, err := sendSMS(msgToCustomer)
	if err != nil {
		return 0.0, err
	}

	costForSpouse, err := sendSMS(msgToSpouse)
	if err != nil {
		return 0.0, err
	}

	return costForCustomer + costForSpouse, nil
}

Creating errors

import "errors"

// Simplest: a fixed message
func divide(x, y float64) (float64, error) {
	if y == 0 {
		return 0.0, errors.New("no dividing by zero")
	}
	return x / y, nil
}

// With formatting
err := fmt.Errorf("SMS that costs $%.2f to be sent to '%v' can not be sent", cost, recipient)
Style

Error messages start lowercase and have no trailing punctuation, because they're often joined into longer messages: "failed to save: no dividing by zero".

Custom error types

Because error is an interface, any struct with an Error() method can be an error, and it can carry extra data:

type divideError struct {
	dividend float64
}

func (de divideError) Error() string {
	return fmt.Sprintf("can not divide %v by zero", de.dividend)
}

func divide(dividend, divisor float64) (float64, error) {
	if divisor == 0 {
		return 0, divideError{dividend: dividend}
	}
	return dividend / divisor, nil
}

Wrapping and checking errors (Extra)

var ErrNotFound = errors.New("not found") // a "sentinel" error to compare against

func load(id string) error {
	err := db.Find(id)
	if err != nil {
		return fmt.Errorf("loading %s: %w", id, err) // %w wraps, keeping the original
	}
	return nil
}

err := load("42")
if errors.Is(err, ErrNotFound) { /* matches even through wrapping */ }

var de divideError
if errors.As(err, &de) { /* err (or something it wraps) is a divideError */ }
Trailing commas

When a function call or literal spans several lines, the last line needs a comma too, or you get a syntax error:

return fmt.Sprintf(
	"can not divide %v by zero",
	de.dividend, // ← required
)

11. Loops

Go has only one loop keyword: for. It covers every kind of loop.

Classic for loop

for i := 0; i < 10; i++ {
	fmt.Println(i) // 0 to 9
}
Part Runs Example
Initial Once, before the loop i := 0
Condition Before each iteration; stop when false i < 10
After After each iteration i++

No parentheses, braces required, just like if.

func bulkSend(numMessages int) float64 {
	totalCost := 0.0
	for i := 0; i < numMessages; i++ {
		totalCost += 1.0 + 0.01*float64(i) // each message: $1 + a growing fee
	}
	return totalCost
}

Omitting parts

Every part is optional. Leaving out the condition loops forever, so you must exit with return or break:

func maxMessages(thresh float64) int {
	totalCost := 0.0
	for i := 0; ; i++ {
		totalCost += 1.0 + 0.01*float64(i)
		if totalCost > thresh {
			return i
		}
	}
}

"While" loop

With only a condition, for acts as a while:

plantHeight := 1
for plantHeight < 5 {
	fmt.Println("still growing! current height:", plantHeight)
	plantHeight++
}

func getMaxMessagesToSend(costMultiplier float64, maxCostInPennies int) int {
	actualCostInPennies := 1.0
	maxMessagesToSend := 0
	for actualCostInPennies <= float64(maxCostInPennies) {
		maxMessagesToSend++
		actualCostInPennies *= costMultiplier
	}
	return maxMessagesToSend
}

And for { ... } with nothing at all is an infinite loop.

FizzBuzz

func fizzbuzz() {
	for i := 1; i <= 100; i++ {
		if i%3 == 0 && i%5 == 0 { // check the most specific case FIRST
			fmt.Println("fizzbuzz")
		} else if i%3 == 0 {
			fmt.Println("fizz")
		} else if i%5 == 0 {
			fmt.Println("buzz")
		} else {
			fmt.Println(i)
		}
	}
}

Order matters: 15 is divisible by 3, so if the i%3 check came first, "fizzbuzz" would never print.

continue and break

Keyword Effect
continue Skip the rest of this iteration and go to the next one
break Exit the loop entirely

continue makes great guard clauses inside loops. Printing prime numbers:

func printPrimes(max int) {
	for n := 2; n <= max; n++ {
		if n == 2 {
			fmt.Println(n)
			continue
		}
		if n%2 == 0 { // even numbers > 2 aren't prime
			continue
		}

		isPrime := true
		for i := 3; i*i <= n; i += 2 { // only check up to √n
			if n%i == 0 {
				isPrime = false
				break // found a divisor: stop the INNER loop
			}
		}
		if !isPrime {
			continue
		}
		fmt.Println(n)
	}
}
  • A prime is a number greater than 1 whose only divisors are 1 and itself.
  • We only test divisors up to √n: any factor bigger than √n pairs with one smaller than √n, which we'd already have found. i*i <= n checks this without floats.
  • break and continue affect only the innermost loop, which is why we need the isPrime flag.

	fmt.Println(i, fruit) // 0 apple, 1 banana, 2 grape
}

for _, fruit := range fruits { /* ignore the index */ }
for i := range 3 { /* Go 1.22+: loops 0, 1, 2 */ }

12. Arrays and slices

Arrays: fixed size

var myInts [10]int                      // 10 zeros
primes := [6]int{2, 3, 5, 7, 11, 13}    // array literal

func getMessageWithRetries() [3]string {
	return [3]string{
		"click here to sign up",
		"pretty please click here",
		"we beg you to sign up",
	}
}

The size is part of the type: [3]int and [4]int are different types. Arrays can never grow or shrink.

Slices: flexible views into arrays

A slice ([]int, no size) is a dynamically sized view into an underlying array. You'll use slices ~99% of the time; arrays mostly exist underneath them.

primes := [6]int{2, 3, 5, 7, 11, 13}
mySlice := primes[1:4] // [3 5 7]: from index 1 UP TO BUT NOT INCLUDING 4
Slice expression Takes
a[low:high] Indexes low … high-1
a[:3] From the start to index 2
a[2:] From index 2 to the end
a[:] Everything (also converts an array to a slice) 
func getMessageWithRetriesForPlan(plan string) ([]string, error) {
	allMessages := getMessageWithRetries() // [3]string array
	if plan == planPro {
		return allMessages[:], nil  // all three, as a slice
	}
	if plan == planFree {
		return allMessages[0:2], nil // first two
	}
	return nil, errors.New("unsupported plan")
}

Returning allMessages directly would fail: cannot use allMessages (variable of type [3]string) as []string value. [:] turns the array into a slice.

Slices are references

A slice doesn't hold data itself; it points to an underlying array. So:

  • Several slices can point to the same array.
  • A function that receives a slice can change the caller's data, even without returning it. This is different from ints, strings and structs, which are copied.

How slices live in memory

Arrays are stored in contiguous memory: one block, elements side by side. That makes iterating fast, but an array can't grow in place, because the memory right after it may belong to another variable.

When a slice outgrows its array, Go automatically:

  1. Allocates a new, bigger array somewhere else.
  2. Copies the old elements across.
  3. Points the slice at the new array.

Copying costs time, which is why capacity exists.

make, len and cap

nums := make([]int, 5, 10) // length 5, capacity 10
nums := make([]int, 5)     // length 5, capacity 5 (capacity defaults to length)
nums := []string{"a", "b", "c"} // slice literal

len(nums) // how many elements the slice currently has
cap(nums) // how big it can grow before a new array must be allocated
len cap
Means Current number of elements Size of the underlying array (from the slice's start)
Care about it for Everyday logic Performance only
On a nil slice 0 (never panics) 0 (never panics)

Pre-allocating when you know the size avoids repeated copying:

func getMessageCosts(messages []string) []float64 {
	costs := make([]float64, len(messages)) // right size from the start
	for i := 0; i < len(messages); i++ {
		costs[i] = float64(len(messages[i])) * 0.01
	}
	return costs
}
Tip

Don't optimise capacity up front. Write simple code first and pre-allocate only when performance actually becomes a problem (or when you obviously know the final size, like above).

Variadic functions

...T lets a function accept any number of arguments, which arrive as a slice:

func sum(nums ...float64) float64 {
	total := 0.0
	for i := 0; i < len(nums); i++ { // nums is a []float64 inside
		total += nums[i]
	}
	return total
}

sum(1, 2, 3) // 6
sum()        // 0

fmt.Println, fmt.Sprintf and append are all variadic. The spread operator passes a slice into a variadic function:

costs := []float64{1, 2, 3}
sum(costs...) // spreads the slice into separate arguments

append

slice = append(slice, oneThing)
slice = append(slice, firstThing, secondThing)
slice = append(slice, anotherSlice...)

append handles growing (allocating a new array if needed) and returns the updated slice.

type cost struct {
	day   int
	value float64
}

func getCostsByDay(costs []cost) []float64 {
	costsByDay := []float64{}
	for i := 0; i < len(costs); i++ {
		c := costs[i]
		for c.day >= len(costsByDay) { // grow until index c.day exists
			costsByDay = append(costsByDay, 0.0)
		}
		costsByDay[c.day] += c.value
	}
	return costsByDay
}
Off-by-one and index panics

A slice of length 4 has indexes 0–3. Accessing index len(s) or beyond panics: index out of range [5] with length 5. That's why the loop above uses >=, not >.

The append pitfall

Always assign append's result back to the same slice.

// ✗ DON'T
someSlice = append(otherSlice, element)

// ✓ DO
someSlice = append(someSlice, element)

Why: if the original slice still has spare capacity, append writes into the same underlying array instead of making a new one. Two "different" slices can then silently share memory:

i := make([]int, 3, 8) // len 3, cap 8: room to grow
j := append(i, 4)      // uses i's array (cap was enough)
g := append(i, 5)      // ALSO uses i's array: overwrites the 4!

fmt.Println(j) // [0 0 0 5]  ← surprise
fmt.Println(g) // [0 0 0 5]

With a small capacity (e.g. cap 3), each append allocates a fresh array and the bug doesn't appear, which makes it even more confusing. Reassigning to the same slice avoids the whole problem.

Slices of slices (2D)

func createMatrix(rows, cols int) [][]int {
	matrix := make([][]int, 0)
	for i := 0; i < rows; i++ {
		row := make([]int, 0)
		for j := 0; j < cols; j++ {
			row = append(row, i*j)
		}
		matrix = append(matrix, row)
	}
	return matrix
}
// createMatrix(3, 3) → [[0 0 0] [0 1 2] [0 2 4]]

Range over a slice

func indexOfFirstBadWord(msg []string, badWords []string) int {
	for i, word := range msg {
		for _, badWord := range badWords {
			if word == badWord {
				return i
			}
		}
	}
	return -1
}

13. Maps

A map stores key → value pairs, like a Python dictionary or a JavaScript object. Looking up a key is instant (constant time), much faster than searching a slice.

ages := make(map[string]int) // map of string keys to int values
ages["John"] = 37
ages["Mary"] = 24

ages := map[string]int{ // map literal
	"John": 37,
	"Mary": 24,
}
fmt.Println(len(ages)) // 2

Operations

Operation Code
Insert / update m[key] = value
Get value := m[key] (missing key → zero value, no panic)
Delete delete(m, key)
Check existence value, ok := m[key] (ok is true if the key exists)
Count len(m)
Iterate for key, value := range m { } (random order) 
func getUserMap(names []string, phoneNumbers []int) (map[string]user, error) {
	if len(names) != len(phoneNumbers) {
		return nil, errors.New("invalid sizes")
	}
	userMap := make(map[string]user)
	for i := 0; i < len(names); i++ {
		userMap[names[i]] = user{name: names[i], phoneNumber: phoneNumbers[i]}
	}
	return userMap, nil
}

Checking if a key exists

func deleteIfNecessary(users map[string]user, name string) (deleted bool, err error) {
	existingUser, ok := users[name]
	if !ok {
		return false, errors.New("not found")
	}
	if existingUser.scheduledForDeletion {
		delete(users, name)
		return true, nil
	}
	return false, nil
}

Maps are references (like slices): delete(users, name) changes the caller's map, even though we don't return it.

Counting with a map

func getCounts(userIDs []string) map[string]int {
	counts := make(map[string]int)
	for _, id := range userIDs {
		counts[id]++ // missing key starts at 0, so this just works
	}
	return counts
}

What can be a key?

Keys must be comparable with ==:

✓ Allowed keys ✗ Not allowed
strings, numbers, booleans, pointers, channels, arrays, structs (of comparable fields) slices, maps, functions

Values can be any type.

Nested maps vs struct keys

A two-level lookup can use nested maps:

hits := make(map[string]map[string]int)
n := hits["/doc/"]["au"] // count of Australians on /doc/

But writing is awkward: you must check that each inner map exists, or writing to a nil inner map panics. A struct key is often simpler:

type key struct {
	path, country string
}

hits := make(map[key]int)
hits[key{"/", "vn"}]++ // one flat map, no inner-map checks

The nested approach, done safely:

func getNameCounts(names []string) map[rune]map[string]int {
	counts := make(map[rune]map[string]int)
	for _, name := range names {
		if name == "" {
			continue
		}
		firstChar := rune(name[0]) // indexing a string gives a byte; convert to rune
		if _, ok := counts[firstChar]; !ok {
			counts[firstChar] = make(map[string]int) // create the inner map first
		}
		counts[firstChar][name]++
	}
	return counts
}
nil maps

Reading from a nil map returns zero values, but writing to a nil map panics: assignment to entry in nil map. Always create maps with make or a literal before writing.

14. Advanced functions

First-class and higher-order functions

  • First-class functions: functions can be stored in variables and passed around like any other value.
  • A higher-order function takes a function as a parameter, or returns one.
func add(x, y int) int      { return x + y }
func multiply(x, y int) int { return x * y }

// higher-order: takes a function
func aggregate(a, b, c int, arithmetic func(int, int) int) int {
	return arithmetic(arithmetic(a, b), c)
}

aggregate(2, 3, 4, add)      // 9
aggregate(2, 3, 4, multiply) // 24

Real uses: HTTP handlers, click and event handlers, callbacks, middleware. Use them when there's a real reason; they add indirection.

func getFormattedMessages(messages []string, formatter func(string) string) []string {
	formatted := []string{}
	for _, m := range messages {
		formatted = append(formatted, formatter(m))
	}
	return formatted
}

Currying

A function that takes a function and returns a new function, usually adding behaviour:

func selfMath(mathFunc func(int, int) int) func(int) int {
	return func(x int) int {
		return mathFunc(x, x)
	}
}

square := selfMath(multiply) // a new func(int) int
double := selfMath(add)

square(5) // 25
double(5) // 10

The main real-world use in Go is middleware: wrapping an HTTP handler to add logic such as authentication (see the project, section 22).

func getLogger(formatter func(string, string) string) func(string, string) {
	return func(a, b string) {
		fmt.Println(formatter(a, b))
	}
}

defer

defer schedules a call to run when the surrounding function returns, however it returns:

func copyFile(dstName, srcName string) (written int64, err error) {
	src, err := os.Open(srcName)
	if err != nil {
		return
	}
	defer src.Close() // runs at the end, on every return path

	dst, err := os.Create(dstName)
	if err != nil {
		return // src still gets closed
	}
	defer dst.Close()

	return io.Copy(dst, src)
}
  • Mostly used for cleanup: closing files, unlocking mutexes, closing response bodies.
  • Multiple defers run in reverse order (last in, first out).
  • Arguments are evaluated when defer runs, not later.

defer also fixes "do X before every return" logic:

func logAndDelete(users map[string]user, name string) (log string) {
	defer delete(users, name) // always delete, after the checks below have run
	u, ok := users[name]
	if !ok {
		return logNotFound
	}
	if u.admin {
		return logAdmin
	}
	return logDeleted
}

Deleting at the top would break the ok check, and repeating delete before each return is error-prone. defer runs it last, exactly once.

Closures

A closure is a function that uses variables from outside its own body. It keeps a reference to them (not a copy), so it can read and change them across calls:

func adder() func(int) int {
	sum := 0
	return func(x int) int {
		sum += x // modifies the enclosed sum
		return sum
	}
}

countAdder, costAdder := adder(), adder() // each has its OWN sum
countAdder(1) // 1
countAdder(1) // 2
costAdder(45) // 45
costAdder(32) // 77

func concatter() func(string) string {
	doc := ""
	return func(word string) string {
		doc += word + " "
		return doc
	}
}

harryPotterAggregator := concatter()
harryPotterAggregator("Mr.")
harryPotterAggregator("and")
harryPotterAggregator("Mrs.") // "Mr. and Mrs. "

Closures are rare in everyday code but essential to understand, because subtle bugs often come from accidentally shared closure variables.

Anonymous functions

Functions with no name, written inline where they're used:

func printReports(messages []string) {
	for _, message := range messages {
		printCostReport(func(m string) int {
			return len(m) * 2
		}, message)
	}
}

Common for callbacks, closures, goroutines (go func() { ... }()) and defer.

15. Pointers

Memory first

Every variable lives at an address in RAM:

Variable Address Value
x 169 5
y := x 170 5 (a copy, at its own address)
z := &x 171 169 (the address of x)

A pointer is a variable whose value is a memory address. z "points to" x.

Syntax

Syntax Meaning Example
*T (in a type) "pointer to T" var p *int
&x Address of x: creates a pointer p := &myString
*p (in an expression) Dereference: the value p points to *p = "new value" 
myString := "hello"
myStringPtr := &myString // type *string

fmt.Println(*myStringPtr) // hello (read through the pointer)
*myStringPtr = "world"    // write through the pointer
fmt.Println(myString)     // world: the original changed

The zero value of a pointer is nil.

Why use pointers?

  1. To let a function change the caller's value. Normally arguments are copied (section 7).
  2. Performance: passing a pointer avoids copying big structs. Only do this when it measurably matters, because shared mutable data causes bugs.
func removeProfanity(message *string) {
	if message == nil { // guard: dereferencing nil panics
		return
	}
	messageVal := *message
	messageVal = strings.ReplaceAll(messageVal, "dang", "****")
	messageVal = strings.ReplaceAll(messageVal, "shoot", "*****")
	messageVal = strings.ReplaceAll(messageVal, "heck", "****")
	*message = messageVal // write back through the pointer
}
nil pointer dereference

Dereferencing a nil pointer panics: invalid memory address or nil pointer dereference. Check if p == nil before using *p whenever a pointer could be nil.

A common mistake is printing a pointer when you wanted the value: &msg prints something like 0xc000010250, a hexadecimal address.

Quick quiz

x := 50
y := &x
*y = 100
// x is now 100: we changed x THROUGH y

Pointer receivers

Methods that modify their struct need a pointer receiver:

type car struct{ color string }

func (c *car) setColor(color string) { // pointer receiver
	c.color = color
}

func (c car) setColorBroken(color string) { // value receiver: works on a copy
	c.color = color
}

c := car{color: "white"}
c.setColor("blue")       // color is now blue
c.setColorBroken("red")  // still blue: the copy was changed
  • Pointer receivers are more common in real Go code.
  • You can call a pointer method on a plain value (c.setColor(...)); Go automatically takes &c for you.
type email struct {
	message     string
	fromAddress string
}

func (e *email) setMessage(newMessage string) {
	e.message = newMessage
}

16. Packages and modules

Packages

Every Go file belongs to a package, declared on its first line.

package main Any other name (library package)
Builds into An executable program Nothing runnable; code for others to import
Has func main() Yes, required (the entry point) No
Exports functions Pointless (nothing can import a main package) Yes, its public API

If a program compiles but "does nothing" or the build produces no executable, check that the package is main.

Package names and import paths

  • By convention the package name is the last part of its import path: math/rand → package rand; github.com/someone/parser → package parser.
  • It's legal to use a different name, but don't; follow the convention.
  • The standard library has two different rand packages: math/rand and crypto/rand. They share a name but have different import paths.
  • A package is a directory. All .go files in one folder are the same package and can use each other's code without importing. One folder can hold only one package.

Exported names

Capitalisation controls visibility:

func Reverse(s string) string { } // Exported: usable from other packages
func reverse(s string) string { } // unexported: only inside this package

The same rule applies to types, struct fields, constants and variables. This is why JSON struct fields must be capitalised (section 22).

Clean package design

  1. Don't export from main. Nothing can import it, so capitalised names only mislead readers.
  2. Export as little as possible. Everything exported is a promise you must keep supporting. A small public "surface area" is easier to use and maintain.
  3. Keep the exported API stable. Changing or removing an exported function breaks everyone who uses it. Change internals freely; change the API rarely.
  4. Packages shouldn't know about their callers' internals.

17. Concurrency: goroutines and channels

Sequential vs concurrent

Sequential (synchronous) code runs one line at a time, top to bottom. It's simple and predictable, but it uses only one CPU core.

Modern CPUs have many cores. If parts of a program don't depend on each other, they can run at the same time on different cores:

// Block A (must run in order)   // Block B (must run in order)
x := 5                          y := 6
x++                             y--
fmt.Println(x)                  fmt.Println(y)

A and B are independent, so running them in parallel can roughly halve the time. (Concurrency and parallelism are technically different ideas, but these notes treat them together.)

Goroutines

Put go before a function call to run it concurrently in a new goroutine: a lightweight thread managed by the Go runtime.

go doSomething()
// execution continues IMMEDIATELY on the next line
  • You can't capture return values from a go call; it runs independently.
  • Goroutines are cheap: thousands are normal.
func sendEmail(message string) {
	go func() {
		time.Sleep(time.Millisecond * 250)
		fmt.Printf("Email received: '%s'\n", message)
	}()
	fmt.Printf("Email sent: '%s'\n", message)
}
// prints "sent" first, then "received" 250ms later

Channels

Goroutines communicate through channels: typed, thread-safe queues.

ch := make(chan int) // channel of ints

ch <- 69   // SEND: the arrow points INTO the channel
v := <-ch  // RECEIVE: the arrow points OUT of the channel
Sends and receives block
  • A send waits until a receiver is ready to take the value.
  • A receive waits until a value is sent.

This blocking is how goroutines synchronise.

Deadlock

If every goroutine is blocked waiting, nothing can ever proceed: a deadlock. Go detects it and crashes with fatal error: all goroutines are asleep - deadlock!.

// ✗ Sending and receiving on the SAME goroutine with no buffer
func filterOldEmails(emails []email) {
	isOldChan := make(chan bool)
	for _, e := range emails {
		isOldChan <- e.date.Before(cutoff) // blocks forever: nobody is receiving yet
	}
	// ...
}

// ✓ Send from a separate goroutine
func filterOldEmails(emails []email) {
	isOldChan := make(chan bool)
	go func() {
		for _, e := range emails {
			isOldChan <- e.date.Before(cutoff)
		}
	}()
	for range emails {
		isOld := <-isOldChan
		fmt.Println("email is old:", isOld)
	}
}

Tokens: empty structs as signals

Sometimes you only care that something happened, not the value. Send empty structs (struct{}, which use zero memory):

func waitForDBs(numDBs int, dbChan chan struct{}) {
	for i := 0; i < numDBs; i++ {
		<-dbChan // wait for one "ready" token; discard the value
	}
}

Buffered channels

A buffered channel has room for N values, so sends don't block until the buffer is full:

ch := make(chan int, 100) // buffer of 100

func addEmailsToQueue(emails []string) chan string {
	emailsToSend := make(chan string, len(emails)) // big enough for every email
	for _, email := range emails {
		emailsToSend <- email // doesn't block: there's room
	}
	return emailsToSend
}

Closing channels

The sender closes a channel to say "no more values":

close(ch)

v, ok := <-ch // ok is false once the channel is closed AND empty

func countReports(numSentCh chan int) int {
	total := 0
	for {
		numSent, ok := <-numSentCh
		if !ok { // closed: we're done
			break
		}
		total += numSent
	}
	return total
}
Danger

Sending on a closed channel panics. That's why only the sender, the one who knows when it's finished, should close a channel.

Range over a channel

range receives values until the channel is closed:

func fibonacci(n int, ch chan int) {
	x, y := 0, 1
	for i := 0; i < n; i++ {
		ch <- x
		x, y = y, x+y
	}
	close(ch) // ends the range loop below
}

func concurrentFib(n int) {
	ch := make(chan int)
	go fibonacci(n, ch)
	for v := range ch {
		fmt.Println(v) // 0 1 1 2 3 5 8 ...
	}
}

select

select waits on several channels at once and runs the case for whichever is ready first (randomly if several are ready):

func logMessages(chEmails, chSms chan string) {
	for {
		select {
		case email, ok := <-chEmails:
			if !ok {
				return // stop when either channel closes
			}
			logEmail(email)
		case sms, ok := <-chSms:
			if !ok {
				return
			}
			logSms(sms)
		}
	}
}

Check ok before using the value: a closed channel delivers zero values, which aren't real messages.

A default case runs immediately if no channel is ready, making the select non-blocking:

select {
case v := <-ch:
	use(v)
default:
	// nothing ready right now
}

18. Mutexes

Channels pass data between goroutines. A mutex (from mutual exclusion) protects data that several goroutines share, so only one can touch it at a time.

Race conditions

When two goroutines read and write the same data at once, results depend on timing: a race condition. Example: two goroutines both read count = 5, both double it, and both write 10. You expected 20. These bugs are intermittent and painful to debug.

Maps are not safe for concurrent use. Concurrent writes can crash the program with fatal error: concurrent map writes.

sync.Mutex

type safeCounter struct {
	counts map[string]int
	mu     *sync.Mutex
}

func (sc safeCounter) inc(key string) {
	sc.mu.Lock()
	defer sc.mu.Unlock() // always unlocks, whatever the return path
	sc.counts[key]++
}

func (sc safeCounter) val(key string) int {
	sc.mu.Lock() // reads need protection too
	defer sc.mu.Unlock()
	return sc.counts[key]
}
  • Lock(): if another goroutine holds the lock, wait. Only one goroutine holds it at a time.
  • Unlock(): release it so another can proceed.
  • defer Unlock() right after Lock() is the idiomatic pattern; you can't forget it on an early return.
  • Locking makes code correct but slower, because goroutines take turns.

sync.RWMutex

Reading concurrently is safe; only writing is dangerous. A read/write mutex allows many readers or one writer:

type safeCounter struct {
	counts map[string]int
	mu     *sync.RWMutex
}

func (sc safeCounter) inc(key string) {
	sc.mu.Lock() // exclusive: for writing
	defer sc.mu.Unlock()
	sc.counts[key]++
}

func (sc safeCounter) val(key string) int {
	sc.mu.RLock() // shared: many readers at once
	defer sc.mu.RUnlock()
	return sc.counts[key]
}
Holder Other writers (Lock) Other readers (RLock)
A writer holds Lock Wait Wait
Readers hold RLock Wait Allowed (no limit)

Use RWMutex when reads greatly outnumber writes.

19. Generics

Added in Go 1.18, generics (type parameters) let you write one function for many types, with full type safety.

The problem

func splitIntSlice(s []int) ([]int, []int) {
	mid := len(s) / 2
	return s[:mid], s[mid:]
}
// The logic is the same for []string, []bool… but you'd need a copy of this function for each.

Before generics, the workaround was []interface{}, which needs risky runtime type assertions afterwards.

Type parameters

func splitAnySlice[T any](s []T) ([]T, []T) {
	mid := len(s) / 2
	return s[:mid], s[mid:]
}

firstInts, secondInts := splitAnySlice([]int{0, 1, 2, 3}) // T = int
firstStrs, secondStrs := splitAnySlice([]string{"a", "b"}) // T = string
  • [T any] declares a type parameter T; any means "any type is allowed".
  • The compiler knows that what comes out matches what went in.
  • This keeps code DRY (Don't Repeat Yourself).
func getLast[T any](s []T) T {
	if len(s) == 0 {
		var zeroVal T // the zero value of whatever T is
		return zeroVal
	}
	return s[len(s)-1]
}

Constraints

Instead of any, a constraint limits which types are allowed and lets you use their methods:

type stringer interface {
	String() string
}

func concat[T stringer](vals []T) string {
	result := ""
	for _, val := range vals {
		result += val.String() // allowed: every T has String()
	}
	return result
}

type lineItem interface {
	GetCost() float64
	GetName() string
}

func chargeForLineItem[T lineItem](newItem T, oldItems []T, balance float64) ([]T, float64, error) {
	newBalance := balance - newItem.GetCost()
	if newBalance < 0.0 {
		return nil, 0.0, errors.New("insufficient funds")
	}
	oldItems = append(oldItems, newItem)
	return oldItems, newBalance, nil
}

Type lists

An interface can list exact types. This is useful for operators like <:

type Ordered interface {
	~int | ~int8 | ~int16 | ~int32 | ~int64 |
		~uint | ~uint8 | ~uint16 | ~uint32 | ~uint64 | ~uintptr |
		~float32 | ~float64 | ~string
}

func max[T Ordered](a, b T) T {
	if a > b { // allowed: every listed type supports >
		return a
	}
	return b
}

The ~ means "this type or any type built on it" (e.g. type celsius float64). Use a type list when you know exactly which types should qualify. Go 1.21+ also has a built-in max and the cmp.Ordered constraint.

Parametric constraints

Interfaces can have type parameters too:

type customer interface {
	GetBillingEmail() string
}

type biller[C customer] interface {
	Charge(c C) bill
	Name() string
}
// userBiller (Charge(user)) and orgBiller (Charge(org)) both satisfy biller

When to use generics

  • Mostly in libraries and reusable data structures (trees, sets, queues, slice helpers).
  • Application code rarely needs them. Don't force them.
  • The name T is just a convention for a single type parameter; any name works.
Why did generics take so long?

Go deliberately keeps its feature set small: fewer features means less to learn, and any Go code is easy to read. A feature is only added once it's proven essential. Generics were debated for years before landing.

Step 3: JSON helpers

// json.go
func respondWithJSON(w http.ResponseWriter, code int, payload interface{}) {
	data, err := json.Marshal(payload)
	if err != nil {
		log.Printf("Failed to marshal JSON response: %v", payload)
		w.WriteHeader(500)
		return
	}
	w.Header().Add("Content-Type", "application/json")
	w.WriteHeader(code)
	w.Write(data)
}

func respondWithError(w http.ResponseWriter, code int, msg string) {
	if code > 499 {
		log.Println("Responding with 5XX error:", msg) // our bug: log it
	}
	type errResponse struct {
		Error string `json:"error"`
	}
	respondWithJSON(w, code, errResponse{Error: msg})
}
  • json.Marshal turns a struct into JSON bytes.
  • Struct tags like `json:"error"` set the JSON key name. Fields must be exported (capitalised) to appear in JSON at all.
  • 4xx codes are client mistakes; 5xx codes are server bugs, so only those are logged.
  • Every error response has the same shape, {"error": "something went wrong"}, so clients can rely on it.

The handler signature is fixed, so you can't add a database parameter. Instead, make the handler a method on apiConfig:

func (apiCfg *apiConfig) handlerCreateUser(w http.ResponseWriter, r *http.Request) {
	type parameters struct {
		Name string `json:"name"`
	}
	decoder := json.NewDecoder(r.Body)
	params := parameters{}
	err := decoder.Decode(&params)
	if err != nil {
		respondWithError(w, 400, fmt.Sprintf("Error parsing JSON: %v", err))
		return
	}

	user, err := apiCfg.DB.CreateUser(r.Context(), database.CreateUserParams{
		ID:        uuid.New(),
		CreatedAt: time.Now().UTC(),
		UpdatedAt: time.Now().UTC(),
		Name:      params.Name,
	})
	if err != nil {
		respondWithError(w, 400, fmt.Sprintf("Couldn't create user: %v", err))
		return
	}

	respondWithJSON(w, 201, databaseUserToUser(user)) // 201 Created
}

Step 7: authentication with API keys

An API key is a long random secret that identifies a user, so there's no username and password to manage.

-- sql/schema/002_users_apikey.sql
-- +goose Up
ALTER TABLE users ADD COLUMN api_key VARCHAR(64) UNIQUE NOT NULL DEFAULT (
  encode(sha256(random()::text::bytea), 'hex')
);

-- +goose Down
ALTER TABLE users DROP COLUMN api_key;
  • A new migration, so the old one stays untouched.
  • The DEFAULT is required: existing users need a unique, non-null key the moment the column appears.
  • random() → text → bytes → SHA-256 hash → hex gives exactly 64 random hex characters.

RETURNING *;

-- name: GetUserByAPIKey :one
SELECT * FROM users WHERE api_key = $1;

Clients send the key in a header: Authorization: ApiKey <key>.

// internal/auth/auth.go
package auth

// GetAPIKey extracts an API key from the headers of an HTTP request
// Example: Authorization: ApiKey {insert apikey here}
func GetAPIKey(headers http.Header) (string, error) {
	val := headers.Get("Authorization")
	if val == "" {
		return "", errors.New("no authentication info found")
	}

	vals := strings.Split(val, " ")
	if len(vals) != 2 {
		return "", errors.New("malformed auth header")
	}
	if vals[0] != "ApiKey" {
		return "", errors.New("malformed first part of auth header")
	}
	return vals[1], nil
}

Step 8: auth middleware

Every authenticated handler would repeat "read key → look up user → handle errors". Middleware removes that duplication using a closure (section 14):

// middleware_auth.go
type authedHandler func(http.ResponseWriter, *http.Request, database.User)

func (apiCfg *apiConfig) middlewareAuth(handler authedHandler) http.HandlerFunc {
	return func(w http.ResponseWriter, r *http.Request) {
		apiKey, err := auth.GetAPIKey(r.Header)
		if err != nil {
			respondWithError(w, 403, fmt.Sprintf("Auth error: %v", err))
			return
		}

		user, err := apiCfg.DB.GetUserByAPIKey(r.Context(), apiKey)
		if err != nil {
			respondWithError(w, 400, fmt.Sprintf("Couldn't get user: %v", err))
			return
		}

		handler(w, r, user) // call the real handler with the user attached
	}
}

	respondWithJSON(w, 200, databaseUserToUser(user))

A user follows many feeds, and a feed has many followers. That's a many-to-many relationship, stored in a join table:

-- sql/schema/004_feed_follows.sql
-- +goose Up
CREATE TABLE feed_follows (
  id UUID PRIMARY KEY,
  created_at TIMESTAMP NOT NULL,
  updated_at TIMESTAMP NOT NULL,
  user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,

  UNIQUE(user_id, feed_id)

-- +goose Down

UNIQUE(user_id, feed_id) stops a user following the same feed twice. Trying returns a duplicate key value violates unique constraint error.

-- name: CreateFeedFollow :one
INSERT INTO feed_follows (id, created_at, updated_at, user_id, feed_id)

RETURNING *;

-- name: GetFeedFollows :many

The ID alone identifies the row, but checking the owner too means a user can only delete their own follows, even if they somehow learn someone else's follow ID.

		respondWithError(w, 400, fmt.Sprintf("Couldn't parse feed follow id: %v", err))
		return
	}

	err = apiCfg.DB.DeleteFeedFollow(r.Context(), database.DeleteFeedFollowParams{
		ID:     feedFollowID,
		UserID: user.ID,
	})
	if err != nil {
		respondWithError(w, 400, fmt.Sprintf("Couldn't delete feed follow: %v", err))

func urlToFeed(url string) (RSSFeed, error) {
	httpClient := http.Client{
		Timeout: 10 * time.Second, // never hang on a slow feed
	}
	resp, err := httpClient.Get(url)
	if err != nil {
		return RSSFeed{}, err
	}
	defer resp.Body.Close()

	dat, err := io.ReadAll(resp.Body)
	if err != nil {

	rssFeed := RSSFeed{}
	err = xml.Unmarshal(dat, &rssFeed)
	if err != nil {
		return RSSFeed{}, err
	}
	return rssFeed, nil
}

Step 12: the background scraper

A long-running worker that fetches feeds on an interval, several at once:

// scraper.go
func startScraping(db *database.Queries, concurrency int, timeBetweenRequest time.Duration) {
	log.Printf("Scraping on %v goroutines every %s duration", concurrency, timeBetweenRequest)
	ticker := time.NewTicker(timeBetweenRequest)

	for ; ; <-ticker.C { // empty init/condition: runs once immediately, then on every tick
		feeds, err := db.GetNextFeedsToFetch(context.Background(), int32(concurrency))
		if err != nil {
			log.Println("error fetching feeds:", err)
			continue // never stop the scraper because of one failure
		}

		wg := &sync.WaitGroup{}
		for _, feed := range feeds {
			wg.Add(1)
			go scrapeFeed(db, wg, feed)
		}
		wg.Wait() // finish this batch before the next tick
	}
}

func scrapeFeed(db *database.Queries, wg *sync.WaitGroup, feed database.Feed) {
	defer wg.Done()

	_, err := db.MarkFeedAsFetched(context.Background(), feed.ID)
	if err != nil {
		log.Println("Error marking feed as fetched:", err)
		return
	}

	rssFeed, err := urlToFeed(feed.Url)
	if err != nil {
		log.Println("Error fetching feed:", err)
		return
	}

	// save posts (step 13)...
	log.Printf("Feed %s collected, %v posts found", feed.Name, len(rssFeed.Channel.Item))
}
Piece Why
time.NewTicker Sends on ticker.C every interval
for ; ; <-ticker.C Runs the body immediately, then waits for each tick (for range ticker.C would wait first)
concurrency + LIMIT $1 Fetch up to N feeds per batch, each on its own goroutine
sync.WaitGroup Add(1) per feed, Done() when each finishes, Wait() blocks until all are done
context.Background() No request context exists here, so use the global background context
continue / return + log A background worker should log and keep going, never crash

Start it in main, on its own goroutine, before ListenAndServe (which blocks forever):

go startScraping(db, 10, time.Minute)

Step 14: a user's personal feed (JOIN)

Show the newest posts from feeds the user follows:

-- name: GetPostsForUser :many
SELECT posts.* FROM posts
JOIN feed_follows ON posts.feed_id = feed_follows.feed_id
WHERE feed_follows.user_id = $1
ORDER BY posts.published_at DESC
LIMIT $2;
  1. JOIN attaches follow data to each post by matching feed_id.
  2. WHERE keeps only the rows for this user, which drops posts from feeds they don't follow.
  3. ORDER BY … DESC puts the newest first; LIMIT caps the count.

24. Self-check quiz

Does Go run faster than interpreted languages? Does it compile faster than most compiled languages?

Yes to both: it runs faster than Python or JavaScript and compiles faster than C++, Rust or Java. It doesn't usually run faster than Rust or C.

Why is a compiled Go program easy to deploy?

It's a single binary with no runtime dependencies, so the target machine doesn't need Go installed.

What is the Go runtime for?

Code built into every binary that handles garbage collection (cleaning up unused memory) and goroutine scheduling.

What does the 64 in float64 mean?

64 bits.

When should you avoid the default types (int, float64)?

Only when memory or performance is a primary concern.

What's the difference between var x int and x := 0?

Both make an int. := infers the type and works only inside functions.

What does int(2.6) return?

2. Conversion truncates; it doesn't round.

How are Go constants different from JavaScript's const?

Go constants must be computable at compile time; JavaScript's can be computed at runtime.

Printf vs Sprintf?

Printf prints; Sprintf returns the formatted string.

Why use an if initial statement?

Shorter code, and the variable stays scoped to the if block.

Arguments are passed by value. What does that mean?

The function receives a copy, so changes don't affect the caller unless you return the value or pass a pointer.

When should you use naked returns?

Rarely, and only in very short functions. Named return values are fine as documentation.

What is a guard clause?

An early return when a condition is met, which keeps logic linear instead of nested.

Nested vs embedded struct?

Nested is accessed as t.car.model; embedded fields are promoted, so t.model.

How does a type implement an interface?

Implicitly, by having all of its methods. There's no implements keyword.

Do interfaces share implementation like parent classes?

No. Each type still implements every method; interfaces only let different types be used in the same places.

What does the two-value type assertion c, ok := s.(circle) protect against?

A panic when s isn't a circle; ok is just false instead.

What is the underlying type of error?

An interface with one method, Error() string.

What does nil error mean?

Success: nothing went wrong.

What loop keywords does Go have?

Only for, which covers classic, while-style and infinite loops plus range.

continue vs break?

continue skips to the next iteration; break exits the innermost loop.

What is 27 % 6?

3.

Do slices reference arrays, or arrays slices?

Slices reference arrays. Several slices can share one array.

Can a function change a slice's contents without returning it?

Yes. Slices (and maps) are references to shared data.

What do len and cap return for a nil slice?

0. They never panic.

What's the safe way to use append?

Always assign the result back to the same slice: s = append(s, v).

What happens when you read a missing map key? Write to a nil map?

Reading returns the zero value. Writing to a nil map panics.

Which types can't be map keys?

Slices, maps and functions, because they aren't comparable.

What does defer do?

It runs a call when the surrounding function returns, on every return path.

Does a closure get a copy of the outer variable?

No, a reference to the original, so it can modify it across calls.

What do &x and *p mean?

&x gives the address of x (a pointer); *p gives the value p points to.

Which receiver type is more common?

Pointer receivers, because methods often need to modify the struct.

What makes a name exported?

Starting it with a capital letter.

What is a Go module?

A collection of packages released together, defined by go.mod.

go run vs go build vs go install?

run compiles and runs once; build makes an executable here; install compiles and installs the binary globally.

What does go func() { ... }() do?

Runs the anonymous function concurrently in a new goroutine.

Do channel sends and receives block?

Yes, until the other side is ready (or there's buffer space for a send).

Who should close a channel, and why?

The sender, because sending on a closed channel panics, and only the sender knows when it's done.

Receive from a closed channel? From a nil channel?

Closed returns the zero value immediately; nil blocks forever.

How many goroutines can hold a Mutex? An RWMutex read lock?

One. For read locks there's no limit, as long as nobody holds the write lock.

What problem do generics solve?

Writing one type-safe function for many types instead of copies, or unsafe interface{} code.

Where are generics used most?

In library packages and reusable data structures.

Why must JSON struct fields be capitalised?

encoding/json can only access exported fields.

Why is the handler a method on apiConfig?

The handler signature is fixed, so the method receiver is how the database connection gets passed in.

Why add a DEFAULT when adding a UNIQUE NOT NULL column?

Existing rows need a valid, unique value immediately.

What does the auth middleware do?

It reads the API key, loads the user, handles auth errors, then calls the real handler with the user.

Why does the scraper use a WaitGroup?

To fetch a batch of feeds concurrently and wait for all of them before the next tick.
